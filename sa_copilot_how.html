Solution Architect Copilot v0.1 the architecture behind the copilot

Seven bounded specialists.
One engagement.

Behind the four-week story sit seven specialists. One reads the RFP. One reads the room. One holds the promotion gate between the architect's draft and the customer's brief. Each owns a scoped responsibility, remembers across engagements, operates under explicit authority rules, and knows when to halt itself.

The language model is only the substrate. The architecture is everything around it.
01 / the distinction

A chatbot drafts an RFP response. An agent watches one slice of the engagement — and acts on it over weeks.

Most "AI for presales" today is a prompt wrapped around a language model, plus retrieval. It autocompletes. It generates. It forgets. The architecture below is structurally different — not because the underlying model is different, but because of what sits around it.

Generative AI

A bounded specialist

scoped responsibility, over weeks
  • Owns one slice of the engagement
  • Reads specific state — not everything
  • Persists across the engagement and into the library
  • Tracks freshness and decays confidence
  • Holds thresholds and authority rules
  • Can halt, defer, or be promoted
  • Has lifecycle — starts, pauses, archives
  • Produces decisions, not just language
02 / the four properties

One job. Specific state. Over an engagement. With authority to act.

Each specialist below has all four of these. Strip any one of them away and the component collapses back into a prompt-and-response wrapper.

01

Bounded responsibility

One job. The Pricing Translator does not read transcripts. The Stakeholder Reader does not size SKUs. Each specialist owns its slice and only its slice.

02

Scoped state

Specific files. Specific memory. Specific timestamps. Not "all available context." The architecture defines what each agent can read — and what it explicitly cannot — and enforces it.

03

Longitudinal operation

Agents persist across the engagement and into the library. They revisit, compare to prior engagements, decay confidence on stale signals. That isn't completion. That's a continuously-running responsibility.

04

Decision authority

Each agent produces an operational output — not just text. Halts block promotion. Confidence triggers promotion. Hazard flags suppress near-twin re-use. The system acts, in bounded ways.

03 / the seven

What each one owns, and the decision it gets to make.

Each specialist has a name, a kind (structured / narrative / orchestrator), and one line that names the move it makes — the move a prompt-wrapper couldn't. The starred one is the only specialist with the authority to halt a draft.

Specialist Authority What it owns. What it decides. What it refuses.
MentorOrchestrator · not customer-facing
Authority
Routes & schedules
Classifies engagement phase, dispatches scoped questions, surfaces contradictions between specialists, routes outputs to either Drafter or the Brief promotion gate. A chatbot doesn't decide which specialist to ask; it just answers whoever asked it. Six-step operating loop: classify engagement phase → dispatch scoped questions → run specialists in parallel → surface contradictions → route to gates → schedule next checkpoint. Holds the canonical engagement memory. Manages the cadence calendar across an engagement and into the archive.
Assumption TrackerNarrative · the integrity layer
Authority
Halt
Owns the live assumption log. Decides when an inference rests on something the customer has not confirmed. When unconfirmed assumptions block a section, it halts promotion — even if every other specialist is confident. The architectural commitment that prevents the system from bluffing. Every halt becomes a footnote in the customer-facing brief, published, not buried.
Requirement ReaderStructured · the RFP parser
Authority
Demote
Reads the RFP verbatim. Separates requirement clauses from scoring criteria, customer success metrics, and implicit assumptions. Refuses to treat boilerplate as a requirement. Refuses to invent requirements the RFP didn't make. The first agent to run on every engagement. Everything downstream reads from its output.
Engagement LibraryNarrative · prior work
Authority
Hazard flag
Owns the near-twin lookup against prior engagements. Surfaces matches with explicit caveats — what carries over, what doesn't. Flags hazard precedents — engagements that look similar but mislead — as do-not-copy, not as templates. A library, not a template store. Reuse with caveats is the move; reuse without caveats is the failure mode it exists to prevent.
Stakeholder ReaderNarrative · the room
Authority
Surface
Owns the transcript read. Attributes word-choice patterns to speakers. Surfaces unspoken disagreements between stakeholders — refusing to resolve them on the customer's behalf. The IT director's phased / ops director's cutover moment lives here. The agent names the gap; the customer's exec sponsor closes it.
Integration MapperStructured · systems of record
Authority
Self-pause
Owns the integration topology. Computes per-edge confidence — what's confirmed, what's inferred, what's unknown. Pauses itself when it cannot confidently distinguish between two integration platforms; refuses to assume one. EWM vs. legacy WM is six weeks of implementation work. The agent doesn't guess; it asks.
Constraint EngineStructured · trade-off math
Authority
Door state
Owns the trade-off computation across competing paths. Phased vs. cutover. Build vs. buy. In-region vs. multi-region. Refuses to recommend a path when both are legitimate; presents trade-offs with named costs. The architectural commitment to let the customer's exec sponsor make the call that's actually theirs to make.
Pricing TranslatorStructured · scope to SKU
Authority
Uncertainty bands
Owns the scope-to-pricing translation. Maps requirement clauses to product SKUs and editions. Refuses to produce single-number quotes when scope is undefined; emits uncertainty bands and the assumptions that would close them. A range with named assumptions is more useful than a number with hidden ones. The customer learns more from the bands than from the midpoint.
Outcome ReferenceMeta · deferred to V2+
Authority
Not granted
Would compare the current engagement to anonymized prior engagements that ended in different outcomes — won / lost / re-scoped / abandoned. Deliberately not built. The architecture has to earn the right to do this before doing it. Requires 12+ engagements of accumulated data with consented comparison. The decision to defer it is itself an agentic decision.
04 / the unexpected part

Constraints are what makes this credible.

Most agent demonstrations make their agents seem more powerful by making them less constrained. This architecture does the opposite. Every agent above operates under explicit bounds: what it can read, what it can decide, what it must defer on, when it must pause itself.

The inversion

It is the boundaries — not the capabilities — that make this system feel engineered rather than imagined.

Assumption Tracker can halt, but only when an unconfirmed assumption blocks a claim. Integration Mapper can pause itself, but only when platform identity is unconfirmed. Brief cannot receive a draft without the promotion gate firing, ever. Pricing Translator cannot emit a single number when scope is undefined. The Outcome Reference engine is not yet built. Every authority in this system has a matching refusal. That's the difference between agents and prompt chains.

The actual moat
